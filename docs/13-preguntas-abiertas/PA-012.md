# PA-012 — IDs propios de GTM/GA4, eventos de conversión, Consent Mode v2 y gestor de cookies

## Contexto y evidencia
El WordPress actual incluye el contenedor `GTM-TG8LZ5L8`, `Site Kit by Google` y CookieYes (`cky-*`), pero **esas cuentas no pertenecen al titular del nuevo proyecto** y quedan descartadas por completo (al igual que el texto obsoleto con `utma_` de su Política de Cookies). La nueva web en Astro debe usar cuentas e IDs propios configurados por variables de entorno.

## Preguntas concretas
1. ¿Cuáles son tus **nuevos IDs propios** de **Google Tag Manager (`GTM-...`)** y/o **Google Analytics 4 (`G-...`)** que debemos configurar por variable de entorno (`PUBLIC_GTM_ID` / `PUBLIC_GA4_ID`)?
2. ¿Se conectarán etiquetas adicionales dentro de tu contenedor propio (Google Ads, Meta Pixel, Microsoft Clarity) y qué eventos de conversión quieres priorizar (`submit_contacto`, `submit_simulador`, `click_telefono`, `click_whatsapp`)?
3. ¿Confirmas el uso de un **banner de consentimiento nativo ultraligero** compatible con Google Consent Mode v2 y actualizar el inventario real en `/politica-de-cookies/`?

## Resolución (2026-11-19)
- Se dejarán implementadas y documentadas las variables de entorno opcionales **`PUBLIC_GTM_ID`** y **`PUBLIC_GA4_ID`** (inocuas mientras permanezcan vacías) para que el usuario introduzca sus IDs propios posteriormente en Cloudflare Pages / `.env`.
- Confirmada la sustitución de CookieYes por un **banner de consentimiento nativo ultraligero en español** con Google Consent Mode v2 y la actualización completa de `/politica-de-cookies/`.
