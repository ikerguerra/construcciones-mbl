# PA-006 — Hosting, acceso DNS, reglas de redirección 301 y continuidad de Webmail

## Contexto y evidencia
La web actual corre en WordPress y en el pie de página incluye un enlace a `Webmail`. Para migrar a Astro con edge caching, SSL, cabeceras HTTP de seguridad y 393+ reglas `301`/`410`, es necesario definir dónde se alojará y cómo se gestionará el dominio `construccionesmbl.com`.

## Opciones recomendadas
- **Cloudflare Pages** (o **Vercel** / **Netlify**): despliegue continuo desde Git, soporte nativo Astro SSG + funciones serverless para formularios, archivo `_redirects` / reglas en borde para las 393 URLs y `TTFB < 100 ms`.
- Alternativa: servidor/hosting tradicional actual por despliegue estático + `.htaccess` (requeriría solución externa para el endpoint de formularios si se retira PHP o mantener un micro-endpoint).

## Preguntas concretas
1. ¿Dónde están alojados actualmente el dominio y el DNS (`construccionesmbl.com`) y quién gestionará el cambio de registros?
2. ¿Qué plataforma de despliegue preferís (Cloudflare Pages, Vercel, Netlify u otra)?
3. El correo corporativo (`info@construccionesmbl.com`) y el enlace `Webmail` del footer, ¿dependen del hosting actual? ¿Debemos conservar el enlace `Webmail` en el footer o retirarlo de la web pública?
4. ¿Confirmamos mantener el dominio canónico **sin `www.`** (`https://construccionesmbl.com/`) y con **barra final `/`**?
